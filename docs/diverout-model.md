# DIVEROUT 水下調色：反推模型說明

> 版本：2026-10-06。用黑箱測試反推，不是官方實作；目標是盡量重現 DIVEROUT「高 / 標準 / 超高」的輸出。
> 工具：`diverout_cc.py`（直接使用）、`tools/diverout_replica.py`（研究與比對用）。
>
> **本專案收錄**：命令列工具 [`tools/diverout_cc.py`](../tools/diverout_cc.py) 與 App 版 [`lib/methods/diverout.js`](../lib/methods/diverout.js)（WaterTool 的「Diverout_sim」方法）。
> 第 8 節列的研究用程式（`tools/diverout_replica.py` 等）與測試影片沒有收錄。下面指令中的 `diverout_cc.py` 在本專案的路徑是 `tools/diverout_cc.py`。

---

## 1. 一句話結論

DIVEROUT 的影片「AI 調色」實際是一套**逐通道的自動色階（auto-levels）**：
每隔一段時間取一個關鍵幀算出 R、G、B 各自的黑點與白點，中間幀線性內插，再把每個像素線性拉伸。
紅色快沒有時，先用綠、藍**合成紅色**再拉伸。沒有任何銳化、降噪、局部處理或超解析。

---

## 2. 處理流程

```
輸入影片
  │
  ├─ 1. 關鍵幀：段數 N = ceil(片長 / T)，在整支片上平均分布 N+1 個關鍵幀（含頭尾）
  │        T = 0.5 秒（超高）/ 1 秒（高）/ 2 秒（標準）
  │
  ├─ 2. 每個關鍵幀估計 6 個數字：R、G、B 的黑點 lo 與白點 hi
  │        （見第 3 節）
  │
  ├─ 3. 紅色太弱時合成紅色：R' = w·R + (1−w)·(G − k·B)
  │
  ├─ 4. 中間幀：lo、hi、w、k 用前後兩個關鍵幀線性內插
  │
  └─ 5. 每個像素、每個通道：out = clip( (in − lo) / (hi − lo) × 255 )
         → 硬體 H.264 編碼（每 30 幀一個 I 幀，加浮水印）
```

### 2.1 參數一覽

| 項目 | 數值 | 來源 |
|---|---|---|
| 關鍵幀間隔上限 | 超高 0.5 s／高 1 s／標準 2 s，平均分布 | T4、T4a、T5、實拍 60 fps |
| 中間幀 | 黑點、白點線性內插（需要先看過整支片） | T4 閃光與硬切的三角形／斜坡反應 |
| 通道處理 | R、G、B 各自線性拉伸，彼此不混合（紅色合成除外） | T1、T8 C/D 組 |
| 空間 | 整張畫面同一組參數，無局部處理 | T2、T3 |
| 細節 | 無銳化、降噪、低解析推論（高頻比例 1.00） | T5 |
| 決定性 | 同一支片處理兩次，像素完全相同 | 實拍重跑 |

## 3. 黑點、白點的估計

有兩組參數：測試圖上完全吻合的 **synthetic**，以及用實拍片擬合、在真實影片上較準的 **real**（預設）。

### 3.1 real（預設，適合真實潛水影片）

| 通道 | 黑點 lo | 白點 hi |
|---|---|---|
| R | [32,232] 內像素第 0.1 百分位 − 7.6 | 全部像素第 99 百分位 − 3.0 |
| G | 同上 − 7.6 | 全部像素第 99 百分位 + 4.3 |
| B | 同上 − 4.5 | 全部像素第 99 百分位 − 3.3 |

### 3.2 synthetic（測試圖規則）

1. 只用「非平坦」像素：亮度和右側或下方鄰點相差 ≥ 1 碼值。均勻色塊會被忽略（T7、T9a）。
2. 排除 < 32 與 > 232 的像素值。
3. 黑點 = 第 2 百分位 + 偏移（R −10.4／G −13.1／B −14.1）。
4. 白點 = 第 98 百分位 + 偏移（R −3.9／G −0.4／B −1.0）。

這組規則在 T7、T8、T9 測試圖上誤差約 2–5 碼值，但在真實影片上白點會偏差 12–25，所以工具預設用 real。

---

## 4. 紅色合成（紅色太弱時）

```
R' = w·R + (1 − w)·(G − k·B)
k  = 1.18 × mean(G) / mean(B) − 0.40          （限制在 0.1–1.5）
R' 的黑點 = 第 1 百分位 − 1.8，白點 = 第 98 百分位 + 16.2
```

| 畫面紅色平均 | w（原本紅色所佔比例） |
|---|---|
| 0–0.4 | 0（紅色完全由綠、藍合成） |
| 3.5 | 0.28 |
| 14.5 | 0.37 |
| 30 | 0.50 |
| 50 | 0.64 |
| 58 | 0.70 |
| ≥ 60 | 1（不合成，正常拉伸） |

實例：深水片紅色中位數為 0 時，DIVEROUT 的紅色輸出 ≈ 2.3·G − 0.83·B − 14（擬合誤差 1.8）。

## 6. 已知限制

1. **真實影片的白點**：沒有任何簡單統計量能準確預測（G 誤差 ≥ 12、B ≥ 24）。real 參數組是平均起來最好的近似；如果 DIVEROUT 有「AI」，最可能就在這一步。
2. **藍色白點閃爍**：深水片前 6 秒，DIVEROUT 的藍色白點在相鄰關鍵幀之間於約 160 和約 255 間跳動（決定性、非隨機），本模型不會重現這個閃爍；這段藍色誤差約 49。
3. **紅色合成的 k 和 w**：只用 2 段實拍和 T9c 擬合，換水色可能需要再修正。
4. **窄直方圖**（幾乎單色的畫面）：DIVEROUT 拉伸得比本模型少。
5. **純色畫面**：DIVEROUT 本身會輸出整片白或青；本模型行為不同，但兩者都不合理。
6. 浮水印、輸出編碼器與 DIVEROUT 不同，不影響顏色。

## 7. 使用方式（`diverout_cc.py`）

### 安裝

```bash
pip install numpy opencv-python      # 另需 ffmpeg / ffprobe（macOS：brew install ffmpeg）
```

### 基本用法

```bash
python3 diverout_cc.py dive.mp4                      # → dive_cc.mp4（保留音軌）
python3 diverout_cc.py dive.mp4 out.mp4 --max-height 1080   # 4K 片先縮成 1080p，速度快約 4 倍
python3 diverout_cc.py photo.jpg                     # → photo_cc.jpg
python3 diverout_cc.py ./trip_folder                 # 整個資料夾 → ./trip_folder/corrected/
```

### 選項

| 選項 | 預設 | 說明 |
|---|---|---|
| `--mode` | `high` | `high` 每 1 秒、`ultra` 每 0.5 秒、`standard` 每 2 秒重新估計顏色 |
| `--profile` | `real` | `real`：真實影片參數；`synthetic`：測試圖參數 |
| `--strength` | `1.0` | 與原片混合比例：0 = 原片、1 = 完整校正、>1 = 更強 |
| `--max-height` | 不縮 | 處理前縮小（例：`1080`） |
| `--crf` | `18` | 輸出 H.264 品質（數字越小檔案越大、畫質越好） |

### 速度參考（2 核心雲端環境）

1080p 60 fps、21.8 秒影片約 5 分鐘；4K 片建議加 `--max-height 1080`。

### 驗證

在實拍 1 上，`diverout_cc.py` 的輸出和研究版重現程式完全一致（模糊後 RMSE 5.3 / 8.8 / 3.2）。
